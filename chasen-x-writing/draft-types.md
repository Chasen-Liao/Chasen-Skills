# 稿型（必选一个）

| 稿型 | 何时 | 篇幅 |
|---|---|---|
| 口播观点（好奇/自查/吐槽） | 他口述一个判断、好奇查完有结论、随手观点 | 约 80～250 字，2～3 段口语 |
| 分享帖 | 推荐工具/项目/玩法，未自称实测 | 200+ 字，讲透优先（长分享 400～1000 字） |
| 实测帖 | 有真实过程/截图/数字 | 以能复现为准 |
| 快评 | 热点、纯情绪、一个判断 | ≤150 字 |
| X 长文 | 教程、合集、深拆 | 标题 + 导流帖（只存草稿） |

**口播观点是默认优先稿型**。当他用口语讲清观点、或思路是「我好奇→查了一下→发现」时，选它，不要默认拉成分享帖/干货长帖。

## 口播观点骨架（松，可增删）

- 骨架：现象或好奇 → 自己原先以为 → 查完/想完之后发现啥。
- 调研数字与材料默认放稿外备注，不进正文。
- 不要划界段，不要调研百分比墙，禁止机械收尾与结尾硬加提问（见 voice-and-craft.md）。

## 分享帖骨架（可增删）

- 第一人称常用「我整理了 / 我翻了一下 / 最近发现 / 我个人更推荐」；顺手试过照实写「我拿 XX 试了一下」，禁止编造「我实测」与测试数字。
- 介绍新东西必须回答三件事：是什么、解决什么/适合谁、去哪拿。
- 骨架：为什么写（来由） → 是什么 → 2～3 个亮点（能帮你做什么） → 他的个人判断与取舍 → 边界与注意事项放最后（钩子在前风险放最后） → 传送门 👉 裸链接。
- 列表：资源整理、多工具对比允许使用「1、」或「1.」列表，一条一事，讲完立刻贴链接。

## 实测帖骨架

- 真实痛点或反常识结论开头 → 他真实的测试过程/配置/命令 → 实测结果与边界 → 传送门 👉。
- 必须有真实过程；缺数据留【待 Chasen 填写】，绝不编造。

## 快评骨架

- 一句话强判断或强情绪，搭配生活观察或截图，直接推进，不铺垫、不分点。
