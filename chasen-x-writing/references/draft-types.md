# 稿型（必选一个）

> 口播观点是默认优先稿型；规则总纲见 `../SKILL.md`。

| 稿型 | 何时 | 篇幅 |
|---|---|---|
| 口播观点（好奇/自查/吐槽） | 他口述一个判断、好奇查完有结论、随手观点 | 约 80～250 字，2～3 段口语 |
| 分享帖 | 推荐工具/项目/玩法，未自称实测 | 200+ 字，讲透优先（长分享 400～1000 字） |
| 实测帖 | 有真实过程/截图/数字 | 以能复现为准 |
| 快评 | 热点、纯情绪、一个判断 | ≤150 字 |
| X 长文 | 教程、合集、深拆 | 标题 + 导流帖（只存草稿），教程按下方骨架 |

## 口播观点骨架（松，可增删）

- 骨架：具体生活观察或好奇 → 自己原先以为 → 查完/想完之后发现啥
- 禁止论文划界、百分比墙、抽象大词与机械/诱导收尾（`SKILL.md` 铁律第 2、3、5 条）

## 分享帖骨架（可增删）

- 第一人称常用「我整理了 / 我翻了一下 / 最近发现 / 我个人更推荐」；顺手试过照实写「我拿 XX 试了一下」，禁编实测数字（`SKILL.md` 铁律第 9 条）
- 介绍新东西必须说人话回答三件事：
  1. **是什么**：一句话大白话，具象例子先于抽象概念
  2. **解决什么/适合谁**：把功能翻译成人话动作，说清帮读者省了什么操作
  3. **去哪拿**：传送门 👉 裸链接
- 骨架：为什么写（来由） → 是什么（生活化例子） → 2～3 个亮点（人话动作） → 个人判断与取舍 → 边界与成本放最后（`SKILL.md` 铁律第 6 条） → 传送门 👉 裸链接
- 列表：资源整理、多工具对比允许使用 `1.` 或 `1、` 列表，一条一事，讲完贴链接

## 实测帖骨架

- 真实痛点或反常识结论开头 → 真实的测试过程/配置/命令 → 实测结果与边界 → 传送门 👉
- 必须有真实过程与真实数字（缺数据按 `SKILL.md` 铁律第 9 条留占位）

## 快评骨架

- 一句话强判断或强情绪，搭配生活观察或截图，直接推进，不铺垫、不分点

## 教程长文骨架（照着做能跑通）

参考：@0xlangeai《Grok Bot 和 WorkBuddy 双向打通保姆级教程》

1. 开头一个真实场景：谁、在哪、遇到什么问题（例：`微信里有人丢来一张 AI 发布截图，问这句话是真的吗`）
2. 一两句话交代整条链路怎么走，用读者看得见的东西说，不画架构
3. 分 3～5 步，每一步都写：
   - 这一步要干什么（一句话）
   - 现成的 prompt 或命令（单独放代码块，读者直接复制）
   - 看到什么就算过了
   - 卡住了先查哪里（可选）
4. 术语第一次出现就用熟悉的东西解释（例：`把 Webhook 想成接单口`）
5. 真实翻车照实写一次，说清楚怎么补上的
6. 技术细节放附录，开头写一句「跟着 prompt 能跑通的话，这段可以跳过」
7. 风险、成本、边界放最后（`SKILL.md` 铁律第 6 条）
8. 带 skill 的教程，「一键发给你的 Bot，直接获得同款」放在手动教程前面
