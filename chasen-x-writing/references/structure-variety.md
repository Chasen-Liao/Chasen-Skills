# 结构轮换指南：避免每篇都像同一套模板

> 本文件只管结构形状轮换与编号细则，全局铁律以 `../SKILL.md` 为准；个人语料与时段校准模板见 [style_guide.md](style_guide.md)。

## 一、通用版式原则

- **列表不是曝光来源，内容才是**：观点与感想不需要强行分点；只有在真有先后操作步骤、安装配置或多工具对比时才使用列表。
- **分段节奏优于一整块文字**：中短帖拆成 2～4 个短段更适合手机阅读，单段高互动通常仅见于极短一句话快评。
- **表情少用点睛**：日常正文 0～1 个表情更耐读，不以表情堆砌代替信息量（特例规则见 `../SKILL.md` 铁律第 7 条）。
- **结尾落地**：落在具体观点、轻自嘲或行动号召上，不以机械总结或硬凑互动的反问句收尾。

## 二、让文字像「人写的」常见写法

- **自然旁白与适度拆台**：少用多重括号，改用破折号或另起一句补充（如「——也可能我打开方式不对」）。
- **克制使用自然口癖**：贴合真实语气，没有真情绪不硬塞夸张感叹词。
- **具体生活或工程细节**：落到真实场景、具体命令、版本号或报错现象，而不是抽象形容词。
- **段落长短错落**：长段后可接一句短段做节奏停顿，不必刻意在句子层面制造长短交替。
- **先打预防针**：引用外部信息时自然标注「按官方文档」「仅代表当前版本」，提升可信度。
- **开头与读者价值**：第一句给出画面、冲突或结论，让读者愿意点开「展开」；正文提供能复用、能省时间或能帮做判断的信息。

## 三、轮换模板：6 种常用结构形状

同一批稿件中相邻两篇不重复同一种形状；交 3 篇以上至少覆盖 3 种形状：

| # | 形状 | 适用场景 | 写法要点 | 示例骨架 |
| :--- | :--- | :--- | :--- | :--- |
| ① | **一句话快评** | 抢热点首发、强观点、情绪共鸣 | ≤40 字，最好配图，最多 1 个点睛表情或「。。。」 | 强判断 + 一处关键事实/截图 |
| ② | **短句连发（3–5 行不空行）** | 热点表态、连续推进几步 | 每行一个意思，最后一行自然反转或轻自嘲 | 事实 → 影响 → 个人反转态度 |
| ③ | **一口气一整段** | 讲清单个判断或发现（80–200 字） | 结论放首句，后面顺着逻辑一气呵成，不分点 | 设问/结论开头 → 直接讲透原因 |
| ④ | **故事 → 观点** | 个人经历、绕弯路、真实场景片段 | 先写具体时间/物件/发生了什么，最后一句落观点 | 具体故障现场 → 顺带得出的判断 |
| ⑤ | **钩子 + 3–5 段（无列表）** | 中长干货、发现、对比（150–600 字） | 首句抛痛点或反常识，每段一意，至少一段仅一句 | 痛点钩子 → 3 段展开 → 成本/边界 → 传送门 |
| ⑥ | **实测长帖（局部带列表）** | 真有安装步骤、配置或复现命令 | 主体写段落，仅步骤处用编号，符号跨篇轮换 | 痛点实测 → 3 步命令与验收信号 → 结论 |

常用变体：
- **问答式**：开头设问，下一段直接作答，适合科普；不用反问收尾。
- **对比两栏**：「宣传说的 / 实际跑下来」，适合工具评测与实操对比。

## 四、编号使用细则

- **默认不用编号**：只有存在先后顺序的操作步骤或配置清单才编号；观点、感受与背景一律写成段落。
- **符号轮换**（严禁使用数字 emoji 当编号，见 `../SKILL.md` 铁律第 7 条）：
  - `1. 2. 3.` 或 `① ② ③`：短步骤流程
  - `-` / `•`：并列小项或对比
  - 「先……再……最后……」：直接融进自然段落
- **预告式列表**：长帖可在开头用 3 条极短清单点题，随后展开正常段落。
