# 声音、正反例与事实分层

## 最高优先级：像真人在说话

读起来要像跟朋友口播聊天，一看就懂，不说黑话，不写抽象报告。
篇幅和节奏跟着口播思路走，规则总纲见 `../SKILL.md`。个人特有口癖与真实语料通过私有配置覆写。

### 正例（通用口播观点示例）

```text
好久没看到有人聊重型 Agent 编排框架了，前阵子大家搭工作流几乎都要先套一层大框架

这两周翻了一圈新项目才发现，很多人已经直接换成原生 SDK 加轻量工具链，代码量少了一大半，排查问题也直观得多
```

为什么好：两段口语、一个自然转折、具体工程观察、没有「先说清楚」、没有百分比墙、没有结尾互动反问。

### 反例（常见代写烂稿症状，禁止再现）

- 「先说清楚：A 是……B 是……」论文划界
- 把调研百分比或多家云厂商名单硬堆进正文充当权威感（调研材料放稿外）
- 一段 taxonomy、一段调研、一段结论、一段提问，像小论文
- 「所以要是现在还有人把……当成标准答案，可能已经偏了」总结腔变体
- 为凑互动硬加「有没有人也……你们那边……」

## 事实分层

分清实测 / 作者判断 / 别人说 / 已核实事实；没做过的不写第一人称（`../SKILL.md` 铁律第 9 条）；分享帖第一人称常用「我整理了 / 我翻了一下 / 最近发现 / 我个人更推荐」，顺手试过照实写，不拔高成实测。

---

## 声音与标点习惯

- 像跟同好聊天；自然使用「感觉」「其实」「翻了一下」「才知道」「。。。」等口语过渡
- 情绪口癖可选不硬塞，无真情绪不硬加
- 英文术语第一次用白话解释；少用冒号和括号；口播短帖少用句号「。」
- 设问句可以用，但不用反问收尾
- 禁大词与去 AI 味对照表见 [plain-talk.md](plain-talk.md)
