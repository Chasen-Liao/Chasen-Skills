# 声音、正反例与事实分层

## 最高优先级：像他本人在说话

读起来要像他跟群友口播聊天，一看就懂，不说黑话，不写抽象报告

读者在手机上刷推只有两三秒注意力，任何抽象名词、没有画面的概念、空洞的大词，都会让人直接划走

Chris 公式、8 型只在冲浏览或收藏且他明确要「冲」时当可选加速器；默认先写成他本人会发的口吻；篇幅和节奏跟着他的口播走，不要擅自扩成调研长文

### 正例（他自己 2026-11-05 发的口播观点）

```
好久没在推上看到有人聊 LangChain 了，这玩意25年年初到 Codex 问世之前都属于是 Agent 框架里的大哥大了

Codex 火起来了之后感觉这玩意就一夜销声匿迹了一样，想到这里的时候，我还觉得可能现在很多企业会用，但去查了一波才知道，大家现在都是用 SDK，或者说是 Pi 这类比较轻量级的 Agent 框架
```

为什么好：两段口语、一个转折、具体场景、没有「先说清楚」、没有百分比、没有结尾互动提问；「这玩意」「感觉」「去查了一波」「才知道」才是他的声音

### 反例（同题代写烂稿症状，禁止再现）

- 「先说清楚：A 是……B 是……」论文划界
- 把 Berkeley 85%、Stack Overflow 30%、Bedrock/Azure/Vertex 堆进正文当权威感
- 一段 taxonomy、一段调研、一段结论、一段提问，像小论文
- 「所以要是现在还有人把……当成标准答案，可能已经偏了」总结腔变体
- 为凑互动硬加「有没有人也……你们那边……」

调研数字默认放**稿外备注**；只有他说「要带数据 / 写成干货长帖」才进正文，且要用他的话串，不要报告体

## 事实分层

分清实测 / 他的判断 / 别人说 / 已核实事实；没做过的不写第一人称，缺数据见 SKILL 铁律第 9 条；分享帖第一人称常用「我整理了 / 我翻了一下 / 最近发现 / 我个人更推荐」，顺手试过照实写，不拔高成实测

---

## 声音与口癖

- 像跟群友说；可用「这玩意」「感觉」「其实」「去查了一波」「才知道」「。。。」
- 情绪口癖（哈哈哈、卧槽、笑死、自嘲等）可选不硬塞，无真情绪不硬加
- 英文术语第一次用白话解释；少用冒号和括号
- 设问句可以用，但不用反问收尾
- 禁大词与去 AI 味见 SKILL 铁律第 2 条与 plain-talk.md
