# 通顺、事实、声音、去 AI 味

## 最高优先级（2026-11-05）

**人味 > 爆款公式。** 读起来要像他跟群友口播，不像调研报告，也不像按模板填空的爆款文。

Chris 公式、8 型、硬钩子只在冲浏览/收藏且他明确要「冲」时当可选加速器；默认先写成他本人会发的口吻。他已经用口语讲清观点时，**篇幅和节奏跟着他的口播走**，不要擅自扩成调研长文。

### 正例（他自己 2026-11-05 发的口播观点）

```
好久没在推上看到有人聊 LangChain 了，这玩意25年年初到 Codex 问世之前都属于是 Agent 框架里的大哥大了

Codex 火起来了之后感觉这玩意就一夜销声匿迹了一样，想到这里的时候，我还觉得可能现在很多企业会用，但去查了一波才知道，大家现在都是用 SDK，或者说是 Pi 这类比较轻量级的 Agent 框架
```

为什么好：两段口语、一个转折、没有「先说清楚」、没有百分比、没有结尾互动提问；「这玩意」「感觉」「去查了一波」「才知道」才是他的声音。

### 反例（同题代写烂稿症状，禁止再现）

- 「先说清楚：A 是……B 是……」论文划界
- 把 Berkeley 85%、Stack Overflow 30%、Bedrock/Azure/Vertex 堆进正文当权威感
- 一段 taxonomy、一段调研、一段结论、一段提问，像小论文
- 「所以要是现在还有人把……当成标准答案，可能已经偏了」总结腔变体
- 为凑互动硬加「有没有人也……你们那边……」

调研数字默认放**稿外备注**；只有他说「要带数据 / 写成干货长帖」才进正文，且要用他的话串，不要报告体。

## 通顺与短叙事

- **通顺**：用因为/所以/但是/尤其是/比如/如果你等连接词串起因果；别一行一短句写成提纲；少用或不用「（）」做解释，术语用人话串进句；「不是 X 而是 Y」每篇最多一次且必须是真对比。
- **短叙事 / 故事帖硬卡**（口播改写、分享过程尤其适用）：
  1. **一段一事**：每一段只推进一个信息点，不要把拆解、沉淀、公开拆成三段进度条。
  2. **一句扛完因果**：能用「把 A 直接写成 B」说完的，不要先写「拆出了」，再另起一句「写进了」。
  3. **禁止同义复述**：正文里同一动作只出现一次；前面说了「写进 skill」，后面禁止再用「做成了 skills / 深度拆解完之后」回炉。
  4. 交稿前出声读一遍：若两句可以并成一句且不丢信息，就并；若某句只是换词重复，就删。

## 事实、声音与排版细节

- **事实**：分清实测 / 他的判断 / 别人说 / 已核实事实。没做过的不写第一人称；缺数用【待 Chasen 填写】绝不编造。分享帖第一人称常用「我整理了 / 我翻了一下 / 最近发现 / 我个人更推荐」，顺手试过照实写，不拔高成实测。
- **声音**：像跟群友说；可用「这玩意」「感觉」「其实」「去查了一波」「才知道」「。。。」；情绪口癖（哈哈哈、卧槽、笑死、自嘲等）可选不硬塞，无真情绪不硬加；英文术语第一次白话解释；少用冒号。
- **去 AI 味**：禁首先其次、综上所述、赋能、对称排比、营销号腔（「家人们」「速看」）。
- **禁机械收尾**：严禁「所以我现在的判断是」「我的结论是」「总结一下」及变体；看法直接写进人话叙述，不要单独起一段宣布自己在下结论。
- **禁互动诱导结尾**：严禁为凑互动硬加结尾提问（「你们觉得呢？」「评论区告诉我」等）。
- **钩子在前风险放最后**：开头直接戳痛点或强判断，边界提醒与注意事项放最后。
- **emoji 规范**：emoji 只放首行末或高潮句，且同一个可重复 3～5 次（如 🔥🔥🔥）；默认 0～1 处当语气词，不滥用、不放段首、不用表情当编号。

## 手机排版三条（v1.1，2026-11-10）

1. 读者几乎都在手机上刷 X，排版以手机竖屏舒服为准，一段两三行就换段，长句拆开，代码块和列表前后空行。
2. 正文不用句号「。」，一句说完就换行，删句号能少点 AI 味，逗号、问号、感叹号照常。
3. 不用「踩坑」这个词，换成「翻车」「被卡住」「绕了弯路」或直接说发生了什么。
4. 交稿前自查：全文 grep「。」和「踩坑」都应为空，代码块里的内容除外。
