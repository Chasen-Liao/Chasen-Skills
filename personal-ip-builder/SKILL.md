# Personal IP Builder — 从参考图到数字资产与教程配图 Skill

> 目标不是「画一张好看头像」，而是交付一整套可支撑自媒体创作的数字资产，并可选地把资产沉淀成 repo-only 教程配图 skill。

## 何时使用

- 用户有一张喜欢的动漫/角色参考图，想做成**自己的**原创个人 IP
- 需要一整套：设定板、头像、立绘、表情动作、内容场景、贴纸，而不只是单张图
- 资产稳定后，要做一个「只给一句话就能出教程配图」的 skill

## 两层交付

| 层 | 交付 | 停点 |
| :--- | :--- | :--- |
| **第一层（默认）** | 整套数字资产 + 资产根目录的 `character-contract.md`：角色设定板、视觉规范板、头像、全身立绘、表情与动作、内容场景、贴纸、横版主视觉 | 用户只要资产，到此结束 |
| **第二层（可选）** | 基于已确认资产创建 **repo-only** 教程配图 skill；skill **引用**仓库内资产与契约，不把 PNG 复制进 skill 目录 | 仅当资产稳定且用户明确要求 |

## 核心原则

1. **输入决定是谁，本 skill 决定做成可复用资产**。参考图只提供情绪、气质与方向，禁止复刻原角色的脸、服装、构图、Logo。
2. **先定身份与契约，再批量生图**。没有确认「角色设计契约」前，不批量生成。
3. **先出设定板，再扩展整套资产**。设定板不过关，不进入头像/表情/贴纸批量。
4. **资产包是终点之一；教程配图 skill 是可选第二终点**。用户只要资产也可以停。
5. **一次一问；单图单核心；白底深灰线稿；角色必须做事**。

## 阶段总览

检查工作区 → 读参考图 → grill-me 设计访谈 → 输出契约并等人确认 → 先设定板再扩展整套资产 → 检查与定向修复 → 可选教程配图 skill

---

## 阶段 0：检查工作区

确认当前目录是用户项目或笔记仓库根目录，并检查：

- 是否已有 `.agents/skills/` 或等价 skills 目录
- 是否已有素材目录如 `03-Assets/` 或用户指定的 assets 路径
- 是否可用 `grill-me`；若无，提示安装：`npx skills@latest add mattpocock/skills`，交互只选 `grill-me`、当前 Project/repo-only，不要全局 `-g`
- 当前环境是否有**支持参考图**的图像生成能力；没有则说明缺口，只交付契约与提示词，不假装已出图

---

## 阶段 1：读参考图

查看用户上传的参考图。参考图只提情绪与方向，禁止复刻原角色。

- 可提取：情绪、比例感、配色记忆点、动作感
- 必须原创化：脸型细节、服装组合、职业身份、品牌配件、固定符号
- 如何与用户真实内容定位连接

不要照着画；把「我喜欢这个角色」转成「想借鉴哪些视觉语言」。

---

## 阶段 2：设计访谈（优先 grill-me）

一次只问一个问题；每个问题给出推荐答案和理由；先定位再外观。问题顺序见 `references/design-interview.md`。

至少确认：

- 内容定位与目标受众
- 动漫化分身还是独立虚构角色
- 性别气质、性格关键词（优先能驱动画面的词，如「好奇行动派」）
- 画风、头身比、发型、眼睛
- 固定服装、主色/辅色、禁用色
- 一个稳定识别配件
- 一个品牌字母或视觉符号
- 内容里最常见的核心动作
- 至少 4 个对应内容生产流程的表情或状态
- 用途：头像 / 教程 / 文章 / 封面 / 贴纸等
- 第一版素材清单

持续维护临时「角色设计契约」，轮次间不丢失已确认项。

---

## 阶段 3：输出角色设计契约

访谈结束后，用简洁完整格式总结并请用户确认。未确认前不生图。契约至少含：

- 名称与 IP 定位
- 性格与说话方式
- 外观硬约束
- 固定配件与品牌标识
- 色彩与线稿规范
- 常用动作与表情
- 使用场景与第一版素材清单
- 原创化边界与禁止事项

确认后把同一份契约写入资产根目录的 `character-contract.md`。

---

## 阶段 4：生成整套数字资产

确认契约后，由 Agent **自动组织提示词并生图**，不要让用户手写长 prompt。

### 默认视觉与构图

- 默认横版 16:9；用户明确要求再用 1:1、4:5、5:2 等
- 纯白背景、深灰手绘线稿、清爽平涂、少量柔和阴影
- 主色、发型、配件、服装、品牌标识全程一致
- 角色必须是画面核心动作主体，必须在做事，不能只站着装饰
- **单图单核心意思**，不把多场景拼成一张多格大图
- 默认不生成文字；仅用户明确提供的 1–5 个短中文词可入图
- 禁止额外角色、第三方 Logo、水印、长段落、复杂 PPT、多余肢体

### 必须交付的资产清单（整套）

按顺序生成，每类单独出图。验收项见 `references/asset-checklist.md`。

1. **角色设定板**：全身主姿势 + 关键识别点 + 核心表情缩略，用来验收一致性
2. **视觉规范板**：配色、线稿、配件、禁止项的一页规范
3. **头像**：正面或半身，适合账号头像与小尺寸卡片
4. **全身立绘**：适合教程与封面动作扩展
5. **表情与动作组**：4–6 个，建议对齐内容流程，例如：发现/专注/翻车/开心分享/疑惑/思考
6. **内容场景组**：角色正在操作界面、排查、讲解流程等，帮助模型理解「角色如何参与教程」
7. **贴纸与反应图**：适合社交媒体与文中情绪节点
8. **横版主视觉**：文章或长文封面可用

设定板未通过前，不要批量生成 3–8。

### 归档目录

保存到用户指定路径，默认：

```text
03-Assets/YYYY-MM-DD-<主题>-personal-ip/
├── character-contract.md
├── 01-角色设定/
├── 02-头像与立绘/
├── 03-表情与动作/
├── 04-内容场景/
└── 05-贴纸与装饰/
```

不覆盖旧版；修订用 `-v2`、`-v3`。保留能复用的设定板与视觉规范板。横版主视觉放进 `01-角色设定/` 或用户指定的封面目录，并在契约里写明路径。

---

## 阶段 5：查看、检查与定向修复

每张图生成后先检查再给人看：

- 是否仍是同一个人：发型、配件、服装、配色、品牌符号
- 角色是否真的在做事，动作是否可读
- 小尺寸下轮廓与配件是否仍可辨
- 是否过满像 PPT；是否意外复刻参考图
- 有无多余肢体、断肢、文字乱码
- 是否仍是白底、深灰线稿、单图单核心

出问题只改一个主因，例如「只删第三只手，其余构图标题不变」。不要整套推倒重来。两轮仍卡在关键缺陷时，交付当前最佳并说明剩余问题。

---

## 阶段 6（可选）：创建教程配图 Skill

资产稳定且用户要求后，创建 **repo-only** 教程配图 skill，不要复制其他 IP 的角色与案例构图，只迁移「解释型配图方法」：

- 用户只给一句教程/流程/工具/概念也能出图
- 不强制读全文
- 默认 16:9，单图单核心
- **角色必须参与核心动作**
- 白底、深灰线稿、用户 IP 配色
- 少量用户提供的中文标注
- 多核心意思拆多张，不合成多格
- 生成后检查一致性、构图、文字、肢体
- 图片保存到 `03-Assets/YYYY-MM-DD-<主题>-ip-illustrations/`
- skill 放在 `.agents/skills/<skill-name>/`，至少含 `SKILL.md`；有 UI 元数据则含 `agents/openai.yaml`
- skill **引用**仓库内资产与 `character-contract.md` 的路径，不要把 PNG 复制进 skill 目录造成双份版本

创建前检查是否已有相似 skill。创建后跑环境可用的校验脚本，并把结果告诉用户。

教程配图 skill 的调用示例应写进该 skill 的 README，例如：

```text
使用 $<tutorial-skill-name>，画一张 16:9 教程配图：
角色正在排查 API 失败，一手扶配件，另一手指向被标出的错误参数。纯白背景，大量留白，不要长文字。
```

## 交付物清单

默认交付：

1. 已确认的 `character-contract.md`
2. 完整数字资产目录（设定板、规范板、头像、立绘、表情、场景、贴纸、主视觉）
3. 简短说明：设计补全了哪些未展示部位；哪些图需要用户审美终审
4. 若用户要求：repo-only 教程配图 skill + 一次真实主题试跑结果

---

## 边界与禁止

- 不在契约确认前批量生图
- 不把参考图当复刻模板；只取情绪与方向
- 不把「一次好看的图」吹成「一条神奇 prompt」
- 不跳过角色一致性检查
- 不把他人 IP、Logo、案例构图拷进资产或 skill
- 不把用户的个人 PNG 资产包提交进本 skill 仓库
- 无生图能力时只交契约与提示词，不假装已出图
