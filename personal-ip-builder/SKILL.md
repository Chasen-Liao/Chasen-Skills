# Personal IP Builder — 做出一套数字资产卡

> 目标不是一次交齐封面、背景图和场景，而是先锁定可派生一切应用图的视觉真源。

## 何时使用

- 用户有一张自己的照片，或一张喜欢的角色参考图，想做成自己的原创个人 IP
- 需要一套可长期复用的数字资产卡，而不是单张好看头像
- 用户说打造个人 IP、做角色设定卡、做数字资产卡，或调用 /personal-ip-builder

## 核心原则

1. **输入决定是谁，本 skill 决定做成可复用资产。** 参考图只借情绪、气质与方向，禁止复刻原角色的脸、服装、构图、Logo。用照片则只保留用户指定的真人特征。
2. **先试定稿，再出资产卡。** 用户没锁定 master 之前，不批量生成。
3. **数字资产卡是真源。** 封面、背景图、日常配图、场景图一律之后按需派生，不在本 skill 开场制作。
4. **生图优先用 Codex image，但不强绑。** 其他工具能跑就跑，先提醒效果可能不稳，并先小样再继续。

## 阶段总览

读参考 → 每轮问 3～5 个问题 → 最多试 3 张定稿图 → 用户锁定 master → 按锁定图出核心资产卡 → 打包成你自己的配图 skill

---

## 阶段 0：检查工作区

确认当前目录是用户项目或笔记仓库根目录，并检查：

- 是否已有素材目录，如 `03-Assets/`，或用户指定的 assets 路径
- 当前环境是否有支持参考图的图像生成能力。没有则说明缺口，只交付契约与提示词，不假装已出图

## 阶段 1：读参考图

查看用户上传的照片或角色参考图，提炼：

- 可提取：情绪、比例感、配色记忆点、想保留的特征
- 必须原创化：脸型细节、服装组合、职业身份、品牌配件、固定符号
- 照片路径：只把用户点名要保留的真人特征写入后续契约，如发型、眼镜、常戴配饰

不要照着画。把「我喜欢这个角色」转成「想借鉴哪些视觉语言」。

若用户还没给图，先请他提供一张照片或喜欢的角色图，不要空转访谈。

## 阶段 2：每轮只问 3～5 个问题

不要一次抛出十几题，也不要默认走 11 轮一次一问。每轮打包 3～5 个问题，给推荐答案，用户答完再问下一轮缺的项。已确认的项跨轮保留，不要重复问。

第一轮优先问这些，能合并就合并：

1. 参考从哪来：照片还是喜欢的角色图，哪些感觉要借、哪些特征必须改成自己的
2. 画风：线稿还是平涂、Q 版还是写实、大致头身比，用一句话说清
3. 别人一眼记住什么：关键外观、固定服装、主色与辅色、一个识别配件。有品牌符号就一并记下
4. 角色是本人分身还是虚构，内容定位用一句话，性格用能驱动画面的词
5. 第一批静态表情要哪 4～6 个状态，对齐内容里最常出现的情绪即可

信息够了就停，不要为了问完清单硬问。用途类问题不要展开成封面、背景图、场景图的制作清单，那些不属于本 skill 的开场产出。

问题包见 `references/design-interview.md`。

## 阶段 3：试定稿，最多 3 张

问题问清后，先出最多 3 张定稿候选图，让用户看清「这个人长什么样」。候选图应是干净的单人物参考，白底或浅底，全身或稳定半身，不要写成设定合页，也不要写成封面或场景。

规则：

- 每张只改一个主因，不要整套推倒重来
- 参考始终回到用户原图与已确认特征，禁止用上一张生成图接着生
- 用户明确说「就这版 / 定稿 / 锁定」之前，不出资产卡，更不批量
- 3 张仍过不了关，交付当前最佳并说明剩余问题，等用户再给方向

锁定后，将该图标为 master，路径写入 `character-contract.md`。后续所有图都以这张 master 为参考真源。

## 阶段 4：按锁定图出核心资产

只交下面这一套，不要自行补封面、背景图、场景图或周边物料。

1. **角色设定卡** 1 张：正面、侧面、背面三视图，加配色条，色值写成 HEX
2. **视觉规范卡** 1 张：干净的定稿参考图，白底或透明底，单人物，供后续生图直接当参考。不要把花哨版式、色板装饰画进这张里
3. **character-contract.md**：固定特征、禁止漂移项、线条与配色规则、master 与规范卡路径，以及一段可直接粘贴的 Character Lock
4. **透明头像** 1 张，加 **静态表情 4～6 个**，均为透明 PNG

默认视觉：浅底或纯白、深灰手绘线稿、清爽平涂、少量柔和阴影。主色、发型、配件、服装全程与 master 一致。默认不生成文字。禁止额外角色、第三方 Logo、水印、复杂版式。

侧面必须是真侧面，背面不得长出正面五官。头像在圆形裁切下，脸和识别配件仍要看得见。表情遮住标签后仍可区分。

出问题只改一个主因。每轮参考必须是已锁定的 master 或视觉规范卡，禁止用上一张生成图接着生。

契约模板见 `references/character-contract.md`，验收见 `references/asset-checklist.md`。

### 归档目录

保存到用户指定路径，默认：

```text
03-Assets/YYYY-MM-DD-<主题>-personal-ip/
├── character-contract.md
├── 01-数字资产卡/
│   ├── 角色设定卡.png
│   └── 视觉规范卡.png
└── 02-头像与表情/
    ├── 头像-透明.png
    └── 表情-01～06-透明.png
```

不覆盖旧版。修订用 `-v2`、`-v3`。

## 阶段 5：生成你自己的配图 skill

资产卡锁定后，最后一步默认为用户生成一个专属配图 skill，把参考图和规则全部打进这个 skill 文件夹，装到任何 Bot 或 Agent 上都能直接用。

```text
<名字>-ip-illustrations/
├── SKILL.md                 # 何时用、怎么按一句话出图、一致性检查
├── character-contract.md    # 从资产包复制
└── assets/
    ├── 角色设定卡.png
    ├── 视觉规范卡.png
    ├── 头像-透明.png
    └── 表情-01～06-透明.png
```

规则：

- 参考图一律放进 skill 自己的 `assets/`，SKILL.md 用相对路径引用，不依赖外部目录
- 生成的配图 skill 只写视觉基础：角色锁定、线条配色、构图习惯、禁止项。不写死封面、背景图、日常配图的具体画幅，用户出图时再告诉生图工具要什么比例
- 资产卡改版后，同步替换 skill 里的 `assets/` 和契约，并在 SKILL.md 里记一行版本
- 生成后告诉用户：这个文件夹可以直接放进自己的 GitHub skill 仓库，以后把地址发给 Bot 就能装

本 skill 自己不出封面、背景图、场景图，这些都交给生成好的配图 skill 按需派生。

## 动态表情

本 skill 不做 GIF 或动态表情。用户需要会动的表情时，把已锁定的设定卡、规范卡和静态表情交给外部 GIF skill 继续做。这是可选项，不绑定某一个仓库。

## 交付物清单

1. 已确认的 `character-contract.md`，其中写明 master 路径
2. 角色设定卡 1 张，视觉规范卡 1 张
3. 透明头像 1 张，静态表情 4～6 个
4. 专属配图 skill 文件夹，`assets/` 内含设定卡、规范卡、头像和表情
5. 简短说明：补全了哪些参考图里没展示的部位，哪些还需要用户审美终审

## 边界与禁止

- 未锁定 master 之前，不出核心资产卡，更不批量
- 不把参考图当复刻模板
- 不把「一次好看的图」吹成「一条神奇 prompt」
- 不跳过角色一致性检查
- 不把他人 IP、Logo、案例构图拷进资产
- 开场不制作封面、背景图、日常配图或场景图
- 不做 GIF 或动态表情
- 无生图能力时只交契约与提示词，不假装已出图
